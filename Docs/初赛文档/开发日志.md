
# 开发日志

## 第七周

本周主要完成了一些初始化工作。一开始原本打算从rcore开始改的，但对比往届参赛作品，发现如果从零开始构建难度较大，而且对于龙芯这种从未接触过的架构，感觉不好改，所以换成基于Tatlin这个。选择Tatlin主要是结构比较清晰，功能比较简单，上手难度低。

## 第八周

本周的主要工作是为TatlinOS实现网络模块。原有的net过于简单，所以为了实现net相关的syscall,本周主要学习了StarryOS的网络模块的设计，引用了StarryOS里面的net模块设计。为了支持net里面的各种操作和数据结构，在原来的内核基础上添加了poll相关的工具在utils文件夹下。同时，为了支持涉及到的异步操作，在task模块中新增了future功能。

## 4.27

修改了fd_table的位置，根据linux源码，fd_table应该由进程进行管理。为了避免，**规定之后的代码必须先获取task的锁再获取process的锁**。为了实现对fd_table成员的迁移，主要对task.rs内的clone_process()函数进行大幅度的修改，确保fd_table的复制和创建最后放入process的内部。

## 5.1

这几天主要进行syscall/fs模块的重构以及对fstruct.rs里面的结构体进行细微调整。

## 第九周

本周主要尝试将原先的工具链进行升级，同时基于OO的设计思想，又重新设计了fstruct.rs的内容。为了实现封装，fstable和fsinfo内部都有自己的锁进行管理，这样就避免还要在进程管理部分考虑两个文件相关的锁。同时本周也重新设计了全局ID分配器，原先的设计里面的循环可能会导致性能的损耗，所以重新设计，将分配和回收的主要逻辑放在id_allocator.rs里面去实现，实现RAII。

## 5.8

今天开始尝试针对ltp测试实现更多的功能，首先是net模块的实现，目前基本框架使用了StarryOS的，还有网络相关的驱动没完成。原来的virtio-drivers版本过低，尝试换成了0.7.5版本。

## 5.11

开始实现第一个系统调用 `sys_socket` , 准备测试用例。

## 5.13

今天完成了对socket进行基础的测试，同时为了初始化net模块，修改了内存布局，使网卡设备的地址能够正常被初始化。

## 5.19

解决ltp测试前几个测例死循环的bug。

## 5.22

针对cgroup_fj测试死循环的问题，通过大模型了解到是因为发送信号的那个任务挂了，所以将相关测试单独拎出来测试。

## 5.23

完善了网络相关的系统调用。使用大模型完善了内核中的几个bug。开始尝试龙芯架构的开发，配置好了相应的工具。

## 5.24

解决龙芯架构下初始化死循环的问题，网卡驱动还是有问题，选择直接跳过

## 5.25

开始针对测试用例进行专门的修改，网卡驱动有问题，暂时不去测net相关涉及通信的。还有其他测例没有进行测试。

## AI 工具使用总结

本节为满足大赛对 AI 工具使用披露的要求而设，详细记录开发过程中 AI 工具的参与情况。更完整的 AI 交互记录见 [AI_INTERACTION.md](./AI_INTERACTION.md)。

### 使用的 AI 工具及模型

| 工具/模型 | 主要用途 |
| ----------- | --------- |
| Cursor | 日志分析、Bug 定位、代码生成、GDB 反汇编分析 |
| Claude Code + DeepSeek-v4 | 复杂 Bug 修复、文档完善、多文件重构 |
| ChatGPT 5.5 | 代码审查、安全性分析、逻辑错误识别 |
| Gemini 3 Flash Preview | 代码理解、注释生成 |

### AI 辅助的关键节点

| 日期 | 问题 | AI 贡献 |
| ------ | ------ | --------- |
| 5月初 | StarryOS 网络模块迁移 | 辅助理解异步网络代码，生成注释和基础测试 |
| 5.15-17 | 网络 syscall 实现与 Bug | Cursor 辅助实现 send/recv 扩展，修复 UDP/TCP 多个 bug |
| 5.19 | 线程5僵尸线程死循环 | Cursor 分析日志发现 Future 强引用导致计数异常 |
| 5.22 | cgroup_fj 死循环 | GPT-5.5 分析根因，建议单独测试策略 |
| 5.23 | translate.rs 安全性问题 | ChatGPT 5.5 审查发现 safe_translated 并不安全 |
| 5.24 | 龙芯 busybox LoadPageFault | Cursor 分析定位 COW 页表标志处理不完整 |
| 5.25 | 龙芯 libcbench 死循环 | Cursor 分析发现 PageModifyFault 读错 fault address 寄存器 |
| 5.26 | RISC-V lmbench 卡死 | Cursor 分析发现 pipe 实现缺少真正的阻塞等待队列 |
| 5.27 | 双架构 glibc-iozone | Claude Code + DeepSeek-v4 修复动态链接路径映射和缺页处理 |

### AI 使用原则

1. 所有 AI 生成的代码均经过人工审查和测试验证
2. AI 主要用于分析定位问题，最终修复方案由人工决策
3. 关键架构决策（如内存布局、并发模型）不使用 AI 生成
