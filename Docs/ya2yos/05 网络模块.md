# 第五章 网络模块

## 5.1 概述

Ya2yOS 的网络模块基于 **smoltcp**（一个嵌入式友好的 Rust 用户态 TCP/IP 协议栈）构建，通过 VirtIO 网络设备驱动实现与外界的网络通信。模块设计参考了 ArceOS 的网络子系统架构，将协议栈、路由管理、套接字接口分层实现。

网络模块是一个可选的编译特性（`feature = "net"`），在构建时通过 Cargo features 控制是否包含。默认构建包含网络功能。

## 5.2 架构分层

网络模块分为四个主要层次：

```
┌─────────────────────────────────┐
│    系统调用接口层 (syscall/net)    │  socket/bind/listen/accept/connect/...
├─────────────────────────────────┤
│    套接字层 (net/socket.rs)       │  Socket trait, TcpSocket, UdpSocket, UnixSocket
├─────────────────────────────────┤
│    协议栈服务层 (net/service.rs)   │  Service::poll() 驱动 smoltcp iface
├─────────────────────────────────┤
│    设备与路由层 (net/device + router)│  EthernetDevice, LoopbackDevice, Router
└─────────────────────────────────┘
```

## 5.3 核心数据结构

### 5.3.1 全局套接字集合（SOCKET_SET）

```rust
static SOCKET_SET: Lazy<SocketSetWrapper> = Lazy::new(SocketSetWrapper::new);
```

`SOCKET_SET` 是全局的套接字集合，内部封装了 smoltcp 的 `SocketSet`，管理所有活跃的网络连接（TCP sockets、UDP sockets、raw sockets）。所有套接字通过 `SocketHandle` 进行索引。

### 5.3.2 监听表（LISTEN_TABLE）

```rust
static LISTEN_TABLE: Lazy<ListenTable> = Lazy::new(ListenTable::new);
```

`LISTEN_TABLE` 跟踪所有处于 LISTEN 状态的 TCP 套接字。当新的 TCP 连接到达时，网络服务通过监听表查找匹配的监听套接字并完成三次握手。

### 5.3.3 路由管理器（Router）

```rust
pub struct Router {
    devices: Vec<Box<dyn NetDevice>>,  // 所有网络设备
    rules: Vec<Rule>,                   // 路由规则
}
```

每个路由规则（`Rule`）包含目标子网、网关、出口设备和源 IP。路由器根据目标 IP 地址匹配路由规则，确定数据包的出口设备和下一跳网关。

### 5.3.4 网络服务（Service）

```rust
pub struct Service {
    router: Router,          // 路由表
    iface: Interface,        // smoltcp 网络接口
    // ... 计时器管理
}
```

`Service` 是网络模块的核心调度器，包装了 smoltcp 的 `Interface`。`poll()` 方法驱动协议栈处理：
1. 从各网络设备的接收缓冲区获取数据包，通过 `router.dispatch()` 交给对应设备处理；
2. smoltcp 协议栈处理 TCP 状态机、重传超时等；
3. 将待发送的数据包从协议栈写入对应网络设备的发送缓冲区。

## 5.4 网络初始化

`init_network(net_devices)` 函数在系统启动时被调用：

1. **创建 Router**，添加两个网络设备：
   - **LoopbackDevice**（lo）：配置为 `127.0.0.1/8`，提供本地回环通信
   - **EthernetDevice**（eth0）：配置 VirtIO 网络设备，使用默认 IP 地址 `10.0.2.15/24` 和网关 `10.0.2.2`（QEMU 用户模式网络默认配置）

2. **添加路由规则**：
   - 到 `127.0.0.0/8` 的数据包通过 loopback 接口
   - 其他所有数据包（默认路由 `0.0.0.0/0`）通过 eth0 接口和网关转发

3. **创建 Service**：将 Router 封装为 Service 单例，初始化 smoltcp `Interface` 的 IP 地址列表。

4. **启动完成**：后续所有套接字操作都通过 `get_service()` 获取 Service 实例。

## 5.5 TCP 套接字实现

### 5.5.1 TcpSocket 结构

```rust
pub struct TcpSocket {
    state: StateLock,                // 连接状态（RwLock<State>）
    handle: SocketHandle,            // smoltcp socket handle
    general: GeneralOptions,         // 通用套接字选项
    rx_closed: AtomicBool,           // 接收端是否关闭
    poll_rx_closed: PollSet,         // 关闭事件的轮询通知
    memberships: RwLock<Vec<(u32, IpAddress)>>,  // 组播组成员
}
```

TCP 的 `State` 枚举跟踪连接状态：
```rust
pub enum State {
    Idle,        // 初始状态
    Connecting,  // 正在连接
    Connected,   // 已连接
    Listening,   // 正在监听
    Closed,      // 已关闭
}
```

### 5.5.2 TCP 操作流程

**被动连接（服务端）：**

1. `socket(AF_INET, SOCK_STREAM, 0)` → 创建 TcpSocket，分配接收/发送缓冲区（各 64KB）
2. `bind(fd, addr)` → 设置本地地址
3. `listen(fd, backlog)` → 将套接字注册到 `LISTEN_TABLE`，状态设为 `Listening`
4. `accept(fd, addr)` → 在 `poll_interfaces()` 驱动下，smoltcp 自动完成三次握手；`accept` 从已完成的连接队列取出新套接字，返回其文件描述符
5. `read/recv` → 从接收缓冲区复制数据到用户态
6. `write/send` → 将用户态数据写入发送缓冲区，smoltcp 在 `poll` 时发送

**主动连接（客户端）：**

1. `socket(...)` → 创建 TcpSocket
2. `connect(fd, addr)` → smoltcp 发起三次握手，套接字状态变为 `Connecting`；在 `poll_interfaces` 驱动下完成握手后变为 `Connected`
3. 之后与被动连接相同，进行数据收发

### 5.5.3 轮询机制

smoltcp 是一个**非阻塞的内核内协议栈**，所有网络事件（数据包收发、超时重传、TCP 状态机推进）都需要通过周期性调用 `poll_interfaces()` 来驱动。Ya2yOS 将 `poll_interfaces()` 集成在时钟中断处理路径中：

```rust
pub fn poll_interfaces() {
    while get_service().poll(&mut SOCKET_SET.inner.lock()) {}
}
```

每次时钟中断到来时，`check_futex_timer()` 和 `poll_interfaces()` 依次被调用，确保网络事件得到及时处理。`poll()` 返回 `true` 表示有更多待处理事件，返回 `false` 表示当前无事可做。

## 5.6 UDP 套接字实现

UDP 套接字相对简单——无需连接状态管理，直接进行数据报的收发：

```rust
pub struct UdpSocket {
    state: StateLock,       // Bound / Connected / Closed
    handle: SocketHandle,
    general: GeneralOptions,
}
```

- `sendto(fd, buf, len, flags, dest_addr)` → 将数据写入 UDP socket 的发送队列，smoltcp 构造 UDP 数据报并通过匹配路由规则的网络接口发送
- `recvfrom(fd, buf, len, flags, src_addr)` → 从 UDP socket 的接收队列取出数据报

UDP 同样支持 `connect` 来设置默认目标地址，之后可使用 `send/recv` 而不是 `sendto/recvfrom`。

## 5.7 Unix Domain Socket

Ya2yOS 实现了 Unix Domain Socket（`AF_UNIX`），支持同一台机器上进程间的通信：

```rust
pub struct UnixSocket {
    state: RwLock<UnixSocketState>,
    addr: RwLock<Option<UnixSocketAddr>>,     // 绑定的地址
    peer_addr: RwLock<Option<UnixSocketAddr>>, // 对端地址
    // ...
}
```

Unix Domain Socket 支持两种模式：
- **SOCK_STREAM**：面向连接的流式通信（类似 TCP），通过内核缓冲区进行数据传输；
- **SOCK_DGRAM**：无连接的数据报通信（类似 UDP）。

## 5.8 套接字选项管理

Ya2yOS 通过 `Configurable` trait 提供统一的套接字选项管理：

```rust
pub trait Configurable: SetSocketOption + GetSocketOption {}
```

支持的选项级别包括：
- `SOL_SOCKET`：通用选项（SO_REUSEADDR、SO_KEEPALIVE、SO_LINGER、SO_RCVBUF、SO_SNDBUF、SO_ERROR 等）
- `IPPROTO_TCP`：TCP 选项（TCP_NODELAY）

## 5.9 Socket 与 File 的统一

网络套接字通过 `File` trait 与文件系统统一：

```rust
pub enum FileClass {
    File(Arc<OSFile>),          // 普通文件
    Socket(Arc<Socket>),        // 网络套接字
    Abs(Arc<dyn File>),         // 抽象文件（管道、eventfd 等）
}
```

`FileClass` 封装了不同类型的文件描述符对象。系统调用通过 `FileClass` 的类型判断（`file()`、`socket()`、`abs()` 方法）来路由到对应的实现。这确保了 read/write/close/poll 等系统调用可以在套接字和普通文件上统一使用。

`Socket` 枚举统一了不同类型的套接字：

```rust
pub enum Socket {
    Tcp(TcpSocket),
    Udp(UdpSocket),
    Unix(UnixSocket),
}
```

## 5.10 数据收发流程

以 TCP `sendmsg` 为例，完整的数据发送路径如下：

1. 用户态调用 `sendmsg(fd, msghdr, flags)` 系统调用
2. 内核从 `msghdr` 中提取发送缓冲区（可能包含多个 iovec）
3. 通过 fd 查找 `FileClass::Socket`，获取 `Arc<Socket>`
4. 匹配 `Socket::Tcp(tcp_sock)`，调用 `TcpSocket::send()`
5. 将用户态数据通过 `UserBuffer` 分批写入 smoltcp TCP socket 的发送缓冲区
6. 在下一个 `poll_interfaces()` 周期，smoltcp 将发送缓冲区中的数据构造为 TCP 段，通过匹配的路由规则发送到对应网络设备的硬件发送队列
7. VirtIO 驱动将数据 DMA 到网卡，完成实际发送

接收路径类似，数据包在 `poll_interfaces()` 中被 smoltcp 协议栈处理后存入对应 socket 的接收缓冲区，用户态通过 `recvmsg` 读取。

## 5.11 网络地址处理

内核负责在 Linux 的 `__kernel_sockaddr_storage` 和 smoltcp 的 `IpAddress` 之间进行地址转换：

```rust
fn extract_ipaddr_from_sockaddr(storage: &__kernel_sockaddr_storage)
    -> SysResult<IpAddress>
```

支持 `AF_INET`（IPv4）和 `AF_INET6`（IPv6）地址族。IPv4 地址从 `sockaddr_in` 结构偏移 4 字节处读取 4 字节；IPv6 地址从 `sockaddr_in6` 结构偏移 8 字节处读取 16 字节。

## 5.12 未来改进方向

1. **零拷贝网络传输**：利用 mmap 的 MAP_SHARED 映射或 splice/sendfile 机制，避免用户态和内核态之间的数据复制；
2. **网络中断驱动**：当前依赖时钟中断轮询驱动网络，引入真正的 VirtIO 网络中断处理可以减少轮询开销和延迟；
3. **IPv6 完善**：当前 IPv6 的基础架构已具备（地址解析），但路由和邻居发现等机制尚未完善；
4. **网络命名空间**：支持容器化的网络隔离；
5. **包过滤/防火墙**：实现 netfilter 或 BPF 框架，提供网络包过滤能力。
