# 第七章 文件系统

## 7.1 概述

Ya2yOS 的文件系统采用 **VFS（Virtual File System）** 分层架构，在用户态系统调用和底层文件系统实现之间建立了统一的抽象层。当前底层文件系统基于 **lwext4**（一个轻量级的 ext2/ext3/ext4 文件系统 C 语言实现库），通过 Rust FFI 绑定集成到内核中。

VFS 层的核心 trait 包括：

```rust
// 超级块抽象
pub trait SuperBlock: Send + Sync {
    fn root_inode(&self) -> Arc<dyn Inode>;
    fn sync(&self);
    fn fs_stat(&self) -> Statfs;
    fn ls(&self);
}

// Inode 抽象（文件/目录的索引节点）
pub trait Inode: Send + Sync {
    fn size(&self) -> usize;
    fn types(&self) -> InodeType;
    fn fstat(&self) -> Kstat;
    fn create(&self, path: &str, ty: InodeType) -> Result<Arc<dyn Inode>, SysErrNo>;
    fn find(&self, path: &str, flags: OpenFlags, loop_times: usize)
        -> Result<Arc<dyn Inode>, SysErrNo>;
    fn read_at(&self, off: usize, buf: &mut [u8]) -> SyscallRet;
    fn write_at(&self, off: usize, buf: &[u8]) -> SyscallRet;
    fn read_dentry(&self, off: usize, len: usize) -> Result<(Vec<u8>, isize), SysErrNo>;
    fn truncate(&self, size: usize) -> SyscallRet;
    fn sync(&self);
    fn set_timestamps(&self, atime: Option<u64>, mtime: Option<u64>,
                      ctime: Option<u64>) -> SyscallRet;
}

// 文件抽象
pub trait File: Send + Sync {
    fn readable(&self) -> bool;
    fn writable(&self) -> bool;
    fn read(&self, buf: UserBuffer) -> SyscallRet;
    fn write(&self, buf: UserBuffer) -> SyscallRet;
    fn poll(&self, events: PollEvents) -> PollEvents;
    fn ioctl(&self, cmd: usize, arg: usize) -> SysResult<usize>;
    // ...
}
```

## 7.2 文件描述符表（FdTable）

### 7.2.1 结构

每个进程拥有一个独立的 `FdTable`（文件描述符表），用于管理进程打开的所有文件描述符：

```rust
pub struct FdTable {
    fds: Vec<Option<FdEntry>>,         // 文件描述符数组
    cloexec_bitmap: SimpleBitmap,       // 标记 CLOEXEC 的 fd
    append_bitmap: SimpleBitmap,        // 标记 APPEND 模式的 fd
    close_on_exec: bool,                // force-close-on-exec 标记
}
```

`FdEntry` 包含文件对象及其打开标志：
```rust
struct FdEntry {
    file: FileClass,        // 文件类型（File/Socket/Abs）
    flags: u32,             // 打开时指定的 flags
}
```

### 7.2.2 文件描述符分配

文件描述符的分配采用**最小可用编号**策略——遍历 fd 数组，返回第一个 `None` 槽位。当达到数组容量上限时自动扩容。`close` 系统调用将对应槽位置为 `None`，该编号即可被复用。

### 7.2.3 Clone 时的共享

当使用 `CLONE_FILES` 标志创建线程时，子线程共享同一 `Arc<FdTable>`（引用计数递增）；不共享时（fork），通过 `FdTable::fork()` 创建独立的深拷贝，每个文件对象通过 `Arc::clone` 共享。

## 7.3 文件系统信息（FSInfo）

`FSInfo` 记录文件系统相关的进程级信息：

```rust
pub struct FSInfo {
    pub cwd: String,        // 当前工作目录
    pub root: String,       // 文件系统根目录
    pub umask: u32,         // 文件创建掩码
}
```

- `cwd`：当前工作目录（current working directory），用于解析相对路径；
- `root`：进程的文件系统根（chroot 可修改），默认 "/"；
- `umask`：新建文件和目录时的权限掩码。

## 7.4 虚拟文件系统（VFS）

### 7.4.1 路径解析

`open()` 函数是 VFS 路径解析的核心入口。路径解析过程：

1. 如果路径不是绝对路径（不以 `/` 开头），则基于当前进程的 `cwd` 拼接为绝对路径；
2. 从根 inode 开始，逐级调用 `inode.find(component, flags)` 遍历路径分量；
3. 对于符号链接：在 `find` 中检测到符号链接后递归解析，`loop_times` 参数防止无限循环（上限通常为 40）；
4. 最终 `open()` 返回 `FileClass`，如果是带 `O_CREATE` 的文件且不存在，则通过 `inode.create()` 创建。

### 7.4.2 挂载管理

`MNT_TABLE` 是全局的挂载表（`Lazy<Mutex<MountTable>>`），管理文件系统的挂载点。`mount` 系统调用允许将块设备上的文件系统挂载到目录树中的指定位置。挂载点查找在路径解析时进行——当路径穿越到挂载点时，后续的 inode 查找切换到挂载设备的根 inode。

支持的挂载标志包括 `MS_BIND`（绑定挂载）、`MS_REC`（递归）等。

## 7.5 ext4 文件系统（lwext4）

### 7.5.1 lwext4 集成

lwext4 是一个轻量级的 ext2/ext3/ext4 文件系统 C 语言实现，Ya2yOS 通过 `lwext4_rust` crate 进行 Rust FFI 绑定。绑定的核心在于实现了 lwext4 所需的块设备接口：

```rust
// lwext4_rust/src/blockdev.rs
pub trait BlockDevice {
    fn read(&self, buf: &mut [u8]) -> Result<i32, SysErrNo>;
    fn write(&self, buf: &[u8]) -> Result<i32, SysErrNo>;
    fn seek(&self, pos: usize);
    fn size(&self) -> usize;
}
```

内核中的 `Disk` 结构被包装为 `BlockDevice` trait 的实现，使得 lwext4 可以直接在 VirtIO 块设备上操作 ext4 文件系统。

### 7.5.2 Ext4Inode

`Ext4Inode` 实现了 VFS 的 `Inode` trait：

- `read_at(off, buf)`：通过 lwext4 的 `ext4_fread` 从文件指定偏移读取数据
- `write_at(off, buf)`：通过 lwext4 的 `ext4_fwrite` 向文件指定偏移写入数据
- `create(path, ty)`：通过 `ext4_dir_entry_add` 在目录中创建新条目（支持文件和目录类型）
- `find(path, flags, loop_times)`：通过 `ext4_dir_find` 查找目录项，返回对应 inode；支持符号链接解析（`ext4_readlink`）
- `fstat()`：返回 `Kstat` 元数据，包括 inode 号、大小、权限、时间戳、链接数等
- `read_dentry(off, len)`：通过 `ext4_dir_get` 读取目录项（用于 getdents64）
- `truncate(size)`：通过 `ftruncate` 截断/扩展文件
- `set_timestamps()`：设置文件访问/修改/创建时间

### 7.5.3 超级块操作

全局超级块提供了以下操作：

- `superblock_root_inode()`：获取根目录 inode
- `superblock_ls()`：列出根目录下的所有文件和目录
- `superblock_fs_stat()`：获取文件系统统计信息
- `superblock_sync()`：同步所有缓存数据到磁盘

## 7.6 普通文件（OSFile）

`OSFile` 是"普通"文件的封装（区别于管道、套接字等特殊文件）。它包含：

```rust
pub struct OSFile {
    readable: bool,                  // 可读标志
    writable: bool,                  // 可写标志
    pub inode: Arc<dyn Inode>,       // 底层 Inode
    inner: Mutex<OSFileInner>,       // 偏移量等可变状态
}
```

文件操作：
- `read(buf)`：根据 `inner.offset` 从 `inode.read_at(offset, buf)` 读取，自动推进偏移量
- `write(buf)`：如果打开时指定了 `O_APPEND`，则先将偏移量定位到文件末尾（`inode.size()`），然后执行写入
- `lseek(offset, whence)`：根据 `SEEK_SET/SEEK_CUR/SEEK_END` 调整文件偏移量
- `ftruncate(size)`：调用 `inode.truncate()` 截断文件

## 7.7 管道（Pipe）

### 7.7.1 Pipe 结构

`Pipe` 实现了工业级的管道通信机制：

```rust
pub struct Pipe {
    readable: bool,
    writable: bool,
    buffer: Arc<Mutex<PipeRingBuffer>>,  // 环形缓冲区（共享）
}
```

```rust
struct PipeRingBuffer {
    arr: [u8; RING_BUFFER_SIZE],  // 固定大小环形缓冲区（通常 64KB）
    head: usize,                   // 读指针
    tail: usize,                   // 写指针
    status: RingBufferStatus,      // 缓冲区状态
    write_end: Option<Weak<Pipe>>, // 写端引用（用于检测写端关闭）
}
```

### 7.7.2 管道读写语义

- **read**：从 `head` 开始读取，推进 `head` 指针。如果缓冲区为空：
  - 非阻塞模式（`O_NONBLOCK`）：立即返回 `EAGAIN`
  - 阻塞模式：将当前线程加入管道的等待队列，阻塞直到有数据可读或写端关闭
- **write**：向 `tail` 写入数据，推进 `tail` 指针。如果缓冲区已满：
  - 非阻塞模式：返回 `EAGAIN`
  - 阻塞模式：将当前线程加入等待队列，阻塞直到有空间可写

### 7.7.3 管道的创建与关闭

```rust
pub fn make_pipe() -> (Arc<Pipe>, Arc<Pipe>);
```

`make_pipe()` 创建一个环形缓冲区，返回读端和写端两个 `Arc<Pipe>`，分别作为 fd 分配给父子进程。

管道关闭时：
- 写端关闭：读端读取到缓冲区中的数据后，下次读取返回 0（EOF）；
- 读端关闭：写端继续写入时收到 `SIGPIPE` 信号（如果进程未忽略此信号则终止）。

### 7.7.4 Pipe2 标志

`pipe2` 系统调用支持以下标志：
- `O_NONBLOCK`：非阻塞模式
- `O_CLOEXEC`：exec 时自动关闭

## 7.8 IO 多路复用

### 7.8.1 epoll

epoll 是 Linux 中高性能的 IO 事件通知机制，Ya2yOS 实现了完整的 epoll 接口：

**EpollFile 结构：**

```rust
pub struct EpollFile {
    registry: Mutex<BTreeMap<usize, EpollEvent>>,  // fd → 监听事件
    ready_list: Mutex<VecDeque<EpollReady>>,        // 就绪事件队列
    poll_set: PollSet,                                 // 用于触发等待者的通知机制
}
```

**三个系统调用：**

1. `epoll_create1(flags)`：创建 epoll 实例，返回一个文件描述符。支持 `EPOLL_CLOEXEC` 标志。
2. `epoll_ctl(epfd, op, fd, event)`：控制 epoll 监听集合：
   - `EPOLL_CTL_ADD`：将 fd 添加到监听集合
   - `EPOLL_CTL_MOD`：修改已监听 fd 的事件掩码
   - `EPOLL_CTL_DEL`：从监听集合中移除 fd
3. `epoll_pwait(epfd, events, maxevents, timeout, sigmask)`：
   - 检查就绪事件队列，如有事件则立即返回
   - 如无事件，阻塞当前线程等待事件通知或超时
   - 支持临时信号屏蔽字替换（`sigmask` 参数）

**事件触发方式：**

当被监听的 fd 上发生 IO 事件时（如 pipe 有数据可读、socket 有新连接），该 fd 的 `poll()` 方法被调用，返回就绪事件。然后通过 `registry` 中的回调将就绪事件加入 `ready_list`，并唤醒 `epoll_wait` 上阻塞的线程。

### 7.8.2 poll / select

除了 epoll 之外，Ya2yOS 还实现了传统的 `ppoll` 和 `pselect6` 接口：

- `ppoll(fds, nfds, timeout, sigmask)`：轮询检查一组文件描述符，返回就绪的 fd 集合
- `pselect6(nfds, readfds, writefds, exceptfds, timeout, sigmask)`：经典的 select 接口

虽然 epoll 在大量并发连接场景下性能远优于 poll/select（O(1) vs O(n)），两者的实现确保了与 Linux 用户态程序的兼容性。

### 7.8.3 EventFD

`EventFd` 是一个特殊的文件类型，用于在线程间传递事件通知：

- `eventfd(initval, flags)`：创建 eventfd，返回文件描述符
- `write`：向 eventfd 写入一个 u64 值，累加到内部计数器
- `read`：读取并清零内部计数器，返回累计值。如果计数器为 0 且存在阻塞的读线程，写操作会唤醒读线程

EventFD 常与 epoll 配合使用，作为线程池中的任务分派信号。

## 7.9 文件状态与元数据

### 7.9.1 Kstat（内核态 stat）

```rust
pub struct Kstat {
    pub st_dev: u64,        // 设备号
    pub st_ino: u64,        // inode 号
    pub st_mode: u32,       // 文件类型和权限
    pub st_nlink: u32,      // 硬链接数
    pub st_uid: u32,        // 所有者 UID
    pub st_gid: u32,        // 所有者 GID
    pub st_size: i64,       // 文件大小（字节）
    pub st_blksize: i32,    // 首选 IO 块大小
    pub st_blocks: i64,     // 分配的块数量
    pub st_atime: i64,      // 最后访问时间
    pub st_mtime: i64,      // 最后修改时间
    pub st_ctime: i64,      // 最后状态变化时间
}
```

`fstat`、`fstatat`、`statx` 等系统调用通过 `inode.fstat()` 获取文件元数据，并转换为 Linux 用户态兼容的 `stat` 结构返回。

## 7.10 内核文件系统（procfs 和内核文件）

### 7.10.1 /proc 目录

`kernel_fs_ops` 模块实现了内核虚拟文件系统（类似 Linux procfs 的子集）：

- `create_proc_dir_and_file(pid)`：为每个进程创建 `/proc/<pid>` 目录及子文件（如 `/proc/<pid>/mem`、`/proc/<pid>/cmdline` 等）
- `remove_proc_dir_and_file(pid)`：进程退出时移除对应的 proc 目录

### 7.10.2 ProcFile

`ProcFile` 是一种内核生成的文件，内容不来自磁盘而是由内核动态计算：
- `/proc/<pid>/mem` 提供对进程内存的访问（通过 ptrace 接口）
- 支持通过 `read` 和 `lseek` 读取内容

### 7.10.3 初始文件系统

`create_init_files()` 在文件系统初始化时调用，确保基本目录结构存在：
- `/`（根目录）
- `/dev`（设备目录）
- `/proc`（进程信息目录）

## 7.11 动态链接支持

`map_dynamic_link` 模块负责加载和映射动态链接程序所需的动态库和动态链接器：

- `map_dynamic_link_file(elf_data)`：解析 ELF 动态段，加载 NEEDED 共享库，执行重定位
- `map_library_path(name, rpath)`：在指定的库搜索路径（如 `/lib`）中查找共享库
- `map_dynamic_link_file_directly_map(name)`：将共享库直接 mmap 到进程地址空间

动态链接器（`ld-linux-*.so`）的映射地址在 `DL_INTERP_OFFSET = 0x15_0000_0000` 附近，确保不与主程序的 ELF 段冲突。

## 7.12 文件 IO 高级操作

Ya2yOS 还实现了以下高级文件操作：
- `sendfile(out_fd, in_fd, offset, count)`：在两个 fd 之间高效传输数据（避免用户态缓冲区中转）
- `copy_file_range(fd_in, off_in, fd_out, off_out, len, flags)`：文件到文件的零拷贝数据复制
- `splice(fd_in, off_in, fd_out, off_out, len, flags)`：在 fd 和管道之间移动数据
- `readv/writev`：分散/聚集 IO，一次系统调用读写多个缓冲区
- `fallocate(fd, mode, offset, len)`：预分配文件空间

## 7.13 未来改进方向

1. **页缓存（Page Cache）**：当前读写直接通过 lwext4 落入块设备，缺少内核级页缓存。引入页缓存可以显著提升文件访问性能，并使 mmap 文件映射能够与文件读写共享相同的物理帧；
2. **更多文件系统支持**：实现 FAT32、devtmpfs、tmpfs 等文件系统，devtmpfs 可以更加自动化地管理 `/dev` 设备节点；
3. **日志文件系统一致性**：利用 ext4 的日志（journal）机制，在内核崩溃后自动恢复文件系统一致性；
4. **文件锁（flock/fcntl）**：实现文件描述符的劝告锁和强制锁机制；
5. **异步 IO 与 io_uring**：当前 `io_uring_setup` 仅返回 stub，实现完整的 io_uring 接口将是大幅提升 IO 性能的关键。
