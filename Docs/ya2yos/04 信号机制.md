# 第四章 信号机制

## 4.1 概述

Ya2yOS 实现了 **Linux 兼容的 POSIX 信号机制**，支持 31 种标准信号（`SIGHUP`～`SIGSYS`）和实时信号。信号机制为内核提供了向进程通知异步事件的能力，包括硬件异常（如 SIGSEGV、SIGILL）、进程间通信（SIGUSR1/SIGUSR2、SIGKILL）、终端控制（SIGINT、SIGTSTP）、任务状态变化（SIGCHLD）等场景。

## 4.2 信号数据定义

### 4.2.1 信号编号

支持标准信号编号 1～31 和一个实时信号（`SIGRTMIN`=32），具体定义与 Linux 保持一致：

```rust
pub const SIGHUP: usize = 1;   // 终端挂起
pub const SIGINT: usize = 2;   // 键盘中断（Ctrl+C）
pub const SIGQUIT: usize = 3;  // 键盘退出（Ctrl+\）
pub const SIGILL: usize = 4;   // 非法指令
pub const SIGTRAP: usize = 5;  // 断点陷阱
pub const SIGABRT: usize = 6;  // abort() 异常终止
pub const SIGBUS: usize = 7;   // 总线错误
pub const SIGFPE: usize = 8;   // 浮点异常
pub const SIGKILL: usize = 9;  // 强制杀死（不可捕获、不可忽略）
pub const SIGSEGV: usize = 11; // 段错误
pub const SIGPIPE: usize = 13; // 管道破裂
pub const SIGALRM: usize = 14; // 定时器超时
pub const SIGTERM: usize = 15; // 终止请求
pub const SIGCHLD: usize = 17; // 子进程状态变化
pub const SIGSTOP: usize = 19; // 停止进程（不可忽略）
pub const SIGCONT: usize = 18; // 继续执行
// ... 其他信号
```

### 4.2.2 信号集（SigSet）

`SigSet` 使用 `usize`（64 位）的位图表示，每位对应一个信号。使用 `bitflags!` 宏提供类型安全的位运算：

```rust
bitflags! {
    pub struct SigSet: usize {
        const SIGHUP    = 1 << (SIGHUP - 1);
        const SIGINT    = 1 << (SIGINT - 1);
        // ... 所有信号的位定义
    }
}
```

`SigSet` 支持交集（`&`）、并集（`|`）、差集（`difference`）等操作，以及 `contains`、`peek_front` 等方法用于遍历置位信号。

### 4.2.3 信号动作（SigAction）

每个信号可以绑定一个 `SigAction`，描述处理方式：

```rust
pub struct SigAction {
    pub sa_handler: usize,      // 信号处理函数地址
    pub sa_flags: SigActionFlags,
    pub sa_restore: usize,     // sigreturn trampoline 地址
    pub sa_mask: SigSet,       // 处理函数执行期间的额外屏蔽信号
}

bitflags! {
    pub struct SigActionFlags: u32 {
        const SA_NOCLDSTOP = 1 << 0;   // 子进程停止时不产生 SIGCHLD
        const SA_NOCLDWAIT = 1 << 1;   // 子进程退出时不转为僵尸
        const SA_SIGINFO   = 1 << 2;   // 使用三参数信号处理函数
        const SA_RESTART   = 1 << 5;   // 自动重启被中断的系统调用
        const SA_NODEFER   = 1 << 6;   // 信号处理时不自动屏蔽当前信号
        const SA_RESETHAND = 1 << 7;   // 调用后重置为 SIG_DFL
        const SA_RESTORER  = 1 << 26;  // 使用自定义 sigreturn 函数
    }
}
```

### 4.2.4 信号表（SigTable）

每个进程拥有一个 `SigTable`，存储 32 个信号的 `KSigAction`，以及线程组的退出状态：

```rust
pub struct SigTableInner {
    actions: [KSigAction; SIG_MAX_NUM + 1],  // 每个信号的处理动作
    group_exit_code: Option<i32>,             // 线程组退出码
}
```

每个 TCB 中还维护线程级别的信号状态：
- `sig_pending: SigSet`：当前线程待处理的信号集
- `sig_mask: SigSet`：当前线程被屏蔽的信号集
- `sig_eintr: bool`：标记当前系统调用是否被信号中断（应返回 EINTR）

## 4.3 信号发送

### 4.3.1 信号发送接口

Ya2yOS 提供了多粒度的信号发送函数：

| 系统调用 | 目标范围 |
|---------|---------|
| `kill(pid, sig)` | pid>0 发送给指定进程组内所有线程；pid=-1 发送给所有进程 |
| `tkill(tid, sig)` | 发送给指定 TID 的单个线程 |
| `tgkill(pid, tid, sig)` | 向指定进程中的指定线程发送信号 |

内核内部信号发送函数：

```rust
// 向整个线程组发送信号
fn send_signal_to_thread_group(pid: usize, sig: SigSet);
// 向单个线程发送信号
fn send_signal_to_thread(tid: usize, sig: SigSet);
// 向除自身外的所有进程发送信号
fn send_access_signal(self_tid: usize, sig: SigSet);
```

### 4.3.2 信号投递流程

`add_signal()` 函数执行实际的信号投递：

1. 将信号位设置到目标 TCB 的 `sig_pending` 中；
2. 如果目标线程处于 `Blocked` 状态，将其状态改为 `Ready` 并加入就绪队列，确保目标线程能够及时处理信号（特别是 SIGKILL 等致命信号）。

### 4.3.3 SIGCHLD 与进程管理

当子进程退出时，内核向父进程发送 `SIGCHLD`。在 `exit_current_and_run_next` 中：

- 当进程所有线程都退出后，内核调用 `send_signal_to_thread_group(ppid, SigSet::SIGCHLD)`；
- 同时通过 `child_exit_event.wake()` 唤醒在 `wait4` 上阻塞的父进程。

### 4.3.4 异常信号

缺页异常、非法指令等硬件异常也会被转换为信号：

- `LoadPageFault / StorePageFault / FetchInstructionPageFault` → 如果页错误处理失败，发送 `SIGSEGV`；
- `IllegalInstruction` → 直接终止进程（exit code = -3）；
- 其他未处理的陷阱 → 内核 panic（内核态异常）或进程终止。

## 4.4 信号处理

### 4.4.1 信号检查时机

信号在 **从内核态返回用户态** 的路径上被检查和处理。在 `trap_return` 函数中：

```rust
pub fn trap_return() {
    // 检查当前任务是否有待处理且未被屏蔽的信号
    if let Some(signo) = check_if_any_sig_for_current_task() {
        handle_signal(signo);
    }
    set_user_trap_entry();
    // ... 恢复用户上下文并返回
}
```

`check_if_any_sig_for_current_task` 检查 `sig_pending & !sig_mask` 中是否有已置位的信号，有则返回最小编号的信号。

### 4.4.2 信号处理分发

`handle_signal(signo)` 根据信号的处理动作（action）分三种情况处理：

**情况一：自定义处理函数**（`customed = true`）

调用 `setup_frame(signo, sig_action)` 在用户栈上构建信号帧（sigframe），修改 TrapContext 使得返回用户态后跳转到信号处理函数执行。

**情况二：默认动作——忽略**

对于某些信号（如 SIGCHLD、SIGURG 等），默认动作是忽略，`handle_signal` 直接返回不做处理。

**情况三：默认动作——终止进程**

对于 SIGSEGV、SIGFPE、SIGILL 等致命信号，默认动作为终止。调用 `exit_current_and_run_next(128 + signo)`，即退出码为 128 加上信号编号（与 Linux 行为一致）。

### 4.4.3 信号帧构建（setup_frame）

信号处理的核心在于在用户栈上构建一个**信号帧**，该帧确保信号处理函数返回后能正确回到内核态并恢复原始上下文。信号帧的布局如下：

**非 SA_SIGINFO 模式（简单信号帧）：**

```
用户栈顶 → [magic: 0xdeadbeef]   ← sp 指向此处
          [sa_siginfo flag: 0]
          [sig_mask 备份]          ← 8 字节
          [MachineContext 备份]     ← 保存原始的 Trap Context
```

**SA_SIGINFO 模式（扩展信号帧）：**

```
用户栈顶 → [magic: 0xdeadbeef]   ← sp 指向此处
          [sa_siginfo flag: MAX]
          [SigInfo 结构体]         ← 信号详情（发送者PID、信号码等）
          [UserContext 结构体]     ← 包含 sigmask、stack、mcontext
```

`setup_frame` 的关键操作：

1. 在用户栈上分配足够空间（先检查栈是否足够，栈不足则终止进程）；
2. 保存当前的 `MachineContext`（Trap 发生时的寄存器快照）；
3. 保存当前的 `sig_mask`；
4. 设置新的信号屏蔽字：`new_mask = sa_mask | (当前信号)`，除非设置了 `SA_NODEFER`；
5. 修改 TrapContext：
   - `sepc` → `sa_handler`（返回用户态时跳转到信号处理函数）
   - `a0` → `signo`（信号编号作为第一个参数）
   - `a1` → `SigInfo` 指针（SA_SIGINFO 模式）
   - `a2` → `UserContext` 指针（SA_SIGINFO 模式）
   - `ra` → `sigreturn_trampoline` 地址（确保处理函数返回时调用 sigreturn）
   - `sp` → 信号帧起始地址

### 4.4.4 信号帧恢复（restore_frame / sigreturn）

当信号处理函数执行完毕、通过 `ret` 返回到 `sigreturn_trampoline` 时，`sigreturn_trampoline` 执行 `sigreturn` 系统调用（syscall id=139）。内核的 `restore_frame()` 函数：

1. 从用户栈读取 `magic = 0xdeadbeef` 校验信号帧的完整性；
2. 读取 `sa_siginfo` 标志确定帧格式；
3. 恢复 `sig_mask`；
4. 恢复 `MachineContext`（包括 sepc、sp、全部通用寄存器）；
5. 返回原始的 a0 值。

恢复完成后，用户态继续从被信号中断的位置（或被 SA_RESTART 重启的系统调用）继续执行。

### 4.4.5 SA_RESTART 与系统调用重入

如果 `SA_RESTART` 标志被设置，且信号中断了一个可自动重启的系统调用，则在信号处理完成后：

- `sepc` 被回退 4 字节（即 `ecall` 指令处）
- `a0` 被恢复为原始调用参数
- 用户态返回到 trap 发生时的指令重新执行系统调用

注意：Ya2yOS 内核是**不可抢占的**（只在从内核返回用户态的路径上处理信号），因此信号不会在系统调用执行过程中中断内核，`SA_RESTART` 在当前架构下主要在 `sigsuspend` 等可被信号唤醒的阻塞系统调用中发挥作用。

## 4.5 信号相关的系统调用

| 系统调用 | 功能 |
|---------|------|
| `sigaction(signo, act, oldact)` | 设置信号处理函数 |
| `sigprocmask(how, set, oldset)` | 修改信号屏蔽字 |
| `sigsuspend(mask)` | 临时替换屏蔽字并挂起等待信号 |
| `sigtimedwait(set, info, timeout)` | 等待信号，支持超时 |
| `sigreturn()` | 从信号处理函数返回（恢复帧） |
| `kill(pid, sig)` | 向进程组发送信号 |
| `tkill(tid, sig)` | 向线程发送信号 |
| `tgkill(pid, tid, sig)` | 向指定线程发送信号 |
| `signalfd4(fd, mask, flags)` | 通过文件描述符读取信号 |

## 4.6 SignalFD

Ya2yOS 实现了 `signalfd4` 系统调用，允许进程通过文件描述符接收信号通知——这在 epoll 事件循环中尤其有用。`SignalFd` 内部维护了一个信号队列，当有信号投递到该进程时（非 SIGKILL 等不可捕获信号），信号被去重后加入队列。用户可以通过 `read` 从 signalfd 中读取 `signalfd_siginfo` 结构体来获取待处理的信号详情。

## 4.7 信号处理的架构兼容性

信号帧构建和恢复通过 `MachineContext` 抽象层屏蔽了架构差异：

- RISC-V64：`MachineContext` 包含 x1-x31 全部通用寄存器，`setup_frame` 在栈上保存整个 `TrapContext` 的快照；
- LoongArch64：类似处理，使用 LA64 的寄存器布局。

`sigreturn_trampoline` 在 RISC-V64 上通过 `extern "C" { fn sigreturn_trampoline(); }` 引用汇编实现的跳板函数，在 LoongArch64 上则通过 `memory_layout::sigreturn_va()` 获取跳板地址。

## 4.8 未来改进方向

1. **实时信号队列**：当前信号的投递采用位图，不支持同一信号的多次排队。实现 `SA_SIGINFO` 基于队列的实时信号机制，可以支持可靠的多实例信号传递；
2. **信号栈（sigaltstack）**：实现 `sigaltstack` 系统调用，允许用户指定备选信号栈，避免在栈空间不足时构建信号帧导致栈溢出；
3. **Core Dump**：在进程因 SIGSEGV、SIGFPE 等信号异常终止时，将进程的内存映像保存为 core dump 文件，便于事后调试分析。
