## 7.2

重构 PCB 与地址空间锁边界：将自带同步的 `MemorySet`、`SigTable`、`FdTable`、`FSInfo` 移出旧 `ProcessInner`，`MemorySet` 内部持有 `RwLock<MemorySetInner>`，`personality` 并入 `ProcessMeta`。

继续重构 PCB 访问接口：移除 `Process::inner_lock()` 和 `ProcessResources` 兼容层，调用点直接通过 `Process` 访问地址空间、信号表、fd 表和 fs 上下文；`make` 通过，QEMU 运行验证本轮未完成。

新增 `ResourceSlot<T>` 资源槽抽象，将 `Process.memory_set` 与 `Process.sig_table` 改为私有可替换槽位，明确区分资源内部同步和进程资源指针替换；`make` 通过，LoongArch64 `make run` 基础测试跑到 `shutdown!`。

继续收敛 PCB 地址空间接口：删除 `get_locked_memory_set_read/write()` 兼容方法，调用点统一使用 `memory_set_arc()`；`make` 通过，LoongArch64 `make run` 基础测试跑到 `shutdown!`。

收敛 pipe 文件描述符分类：`pipe2()` 分配的匿名 pipe 统一存入 `FileClass::Pipe`，`vmsplice` 改为通过 pipe 类型入口校验和写入；默认 LoongArch64 `make` 通过。

实现 `splice(2)` 兼容搬运路径：支持 regular file 与 pipe、pipe 与 regular file、pipe 与 pipe 之间通过内核缓冲区传输，补齐 offset 写回、pipe offset `ESPIPE`、`O_APPEND` 输出 `EINVAL`、`SPLICE_F_NONBLOCK` 基础语义；LoongArch64/RISC-V 构建通过，LoongArch64 `splice01` musl/glibc 均 `TPASS`。详见 problem/。

优化 pipe 内部缓冲结构：将 `PipeRingBuffer` 从字节环改为 `PipeBuf` 片段队列，`splice(pipe, pipe)` 走片段引用移动，`tee()` 走片段引用复制；默认 LoongArch64 `make` 通过。当前 `initproc` 中的 `splice05` 仍暴露 socket splice `ENOTCONN` 语义缺口，需后续单独处理。

接入文件页面缓存到 `MAP_SHARED` mmap 与 `splice(file, pipe)`：共享文件缺页改由 `FILE_PAGE_CACHE` 提供 `FrameTracker`，`PipeBuf` 支持挂载 `FilePage`，普通文件到 pipe 的 `splice` 走缓存页引用 fast path；默认 LoongArch64 `make` 通过，当前 `splice09` 入口因内核版本要求 `TCONF/skipped` 并跑到 `shutdown!`。

修复 pipe LTP 语义：无读端写入 pipe 时先投递 `SIGPIPE` 再返回 `EPIPE`，并实现 `ioctl(FIONREAD)` 返回 pipe 当前可读字节数；默认 LoongArch64 `make` 通过，当前 `pipe02`/`pipe08`/`pipe12` 核心断言均 `TPASS`。详见 problem/。

重构 pipe 源码布局：将原 `os/src/fs/files/pipe.rs` 按功能拆分到 `os/src/fs/files/pipe/`，分别承载片段缓冲、共享 ring buffer、FIFO 表、splice/tee、阻塞等待和 `File` trait 实现；对外 `Pipe`、`make_pipe()`、`open_fifo()` 路径保持不变。默认 LoongArch64 `make` 通过。

## 7.3

将 `FsIndex` 从路径强引用表改为 VFS inode cache：使用 `(st_dev, st_ino)` 归并 inode 身份，路径索引只保存 cache key，inode cache 使用 `Weak` 避免缓存永久持有对象；`Ext4Inode` 增加路径别名以兼容 hard link / rename 后的 path-based lwext4 操作。RISC-V 与 LoongArch64 构建通过，RISC-V QEMU 交互验证 hard link、unlink 原路径、rename 后读取均正常。

修复 RISC-V Alpine 镜像启动期仍按竞赛测试镜像布局写 `/glibc/lib/libgcc_s.so.1` 和覆盖 `/bin/sh -> /musl/busybox` 的问题；动态解释器加载增加精确路径 `open_direct()` 回退，并将解释器加载失败作为 exec 错误传播。`make TARGET_ARCH=riscv64` 通过，25 秒 QEMU 日志未再出现原 ENOENT panic、`exec /bin/sh failed` 或 `FetchInstructionPageFault 0xfffffffffffffffe`。详见 [problem/riscv-alpine-initfiles-dynamic-link.md](./problem/riscv-alpine-initfiles-dynamic-link.md)。

将 `initproc` 调整为默认启动 `/bin/sh -i`，失败时回退 `/musl/busybox sh -i`，并补充 `TERM/HOME/SHELL/USER` 默认环境变量。`make TARGET_ARCH=riscv64` 通过，25 秒 QEMU 日志出现 `/ #` 提示符，可直接交互输入命令。详见 [problem/riscv-alpine-initfiles-dynamic-link.md](./problem/riscv-alpine-initfiles-dynamic-link.md)。

补充控制台 stdin 基础回显，shell 中输入的命令字符、回车和退格现在会显示在 QEMU 串口输出中。`make TARGET_ARCH=riscv64` 通过，延迟输入 `echo SHELL_ECHO_OK` 后日志显示命令本身和执行结果。详见 [problem/riscv-alpine-initfiles-dynamic-link.md](./problem/riscv-alpine-initfiles-dynamic-link.md)。

修复 `vi` 的 `:` 模式输入双回显：stdio 现在支持最小 `TCGETS/TCSETS*` termios，stdin 回显受 `ECHO` 位控制，`ICANON` 关闭时按原始字符返回。`make TARGET_ARCH=riscv64` 通过，QEMU 中 `stty -echo` 后输入命令不再被内核回显，恢复 `stty echo` 后回显正常。详见 [problem/riscv-alpine-initfiles-dynamic-link.md](./problem/riscv-alpine-initfiles-dynamic-link.md)。

修复 `iperf-musl` 后连续运行 `iperf-glibc` 的 5001 端口冲突与 glibc 栈保护失败：socket fd close/exit 主动 shutdown 释放 listener，`TCGETS` 改回 Linux old termios 36 字节布局，并在标准 `run_testsuit()` 收尾时清理被 init 收养的 daemon 子进程。`make` 通过，`/tmp/iperf-generic-cleanup.log` 中 musl/glibc 两轮 iperf 六项均 success，未再出现 `socket already listening on port 5001`。详见 [problem/iperf-port-reuse-termios-stack-smash.md](./problem/iperf-port-reuse-termios-stack-smash.md)。

修复内核资源锁边界重构后 `netperf` 回归：`FdTable::close()` 不再因父进程关闭 accepted fd 而提前 shutdown 子进程继承的控制连接，`FdTable::clear()` 仍在进程退出时主动释放 listening socket，避免 `netperf-glibc` 复用 12865 端口失败。`make` 通过，`timeout 300s make run > log.ans 2>&1` 中 musl/glibc 两轮 netperf 十项均 success。详见 [problem/netperf-glibc-port-reuse.md](./problem/netperf-glibc-port-reuse.md)。

修复 `cyclictest` STRESS 模式下 `hackbench` 大量 `CLIENT: ready write (error: Broken pipe)`：`sys_socketpair()` 不再连续两次 `alloc_fd()` 复用同一空闲 fd，AF_UNIX socket 补齐阻塞 `recv/accept` wake 语义。`make` 通过，`timeout 300s make run > log.ans 2>&1` 中 musl/glibc cyclictest 四项均 success，未再出现 ready 阶段 Broken pipe。详见 [problem/cyclictest-socketpair-fd-allocation.md](./problem/cyclictest-socketpair-fd-allocation.md)。

修复 libctest `clocale_mbfuncs` 全量入口报 `Interrupted system call`：`sigtimedwait(SIGCHLD)` 成功消费信号后现在会清理内部 `interrupt_waker/interrupted` 状态，避免随后 `wait4()` 误返回 `EINTR`。`make` 通过，`make run` 中 clocale 输出 `Pass!`。详见 [problem/libctest-sigtimedwait-eintr.md](./problem/libctest-sigtimedwait-eintr.md)。

修复 LTP `abort01` 中 `tst_test.c:1654` 的 `waitpid(...)=EINTR` `TBROK`：`waitpid/waitid` 不再由通用 `interruptible()` 抢先返回 `EINTR`，而是按 pending signal 与 `SA_RESTART` 语义返回内部 `ERESTART` 并交由 signal frame 重启。`make` 通过，最新 `log.ans` 中 `abort01` 为 `passed 2 failed 0 broken 0`。详见 [problem/waitpid-sa-restart-eintr.md](./problem/waitpid-sa-restart-eintr.md)。
